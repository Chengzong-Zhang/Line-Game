# 生命线游戏开发

把需求落实为可玩、可复现、能说明验证范围的增量成果。默认仓库为 `C:/coding/py/line game`；用户指定其他 checkout 时使用指定位置。当前要求、适用的 `AGENTS.md` 和现场源码优先于旧记录。本技能保存工作方法，不保存实时上线状态，也不延续其他聊天的外部操作授权。

## 按用户的方式推进

- 要求实现就完成代码、相关验证和可用交付；只要求方案、审计或技能更新时保持对应范围。有合理默认值的工程选择自行处理，已有授权不重复询问。外部条件缺失时继续完成不依赖它的部分，最后给最短待办和准确原因。
- 保留成熟体验、视觉和交互，复用 Vue/Canvas、JavaScript 核心、Python 服务及现有平台工程。以“开局 → 完整对局 → 结算 → 复盘/导出 → 恢复”检查受影响的一段闭环，不为渠道重写游戏，不顺带承包全部路线图。
- “同步所有最新功能”先整合各工作树中已完成且可验证的功能，核对目标包包含的修复，不能仅选日期最新的旧包。同步范围及平台差异写清；实验候选保持准入边界。
- 新功能同时检查本地、联机、人机、保存恢复和相关平台的影响。只要求本地时先完成本地并列出同步缺口；要求联机或跨端同步时补齐对应入口、协议、服务和构建。
- 普通对局只展示玩家需要的信息。历史集合、逻辑边、搜索预算和诊断放在复盘/实验室；规则解释贴近局面，中英文和手机操作同步维护。
- 小修复走最短有效验证路径；规则、异步状态、恢复、性能和研究结论需要对应反例或证据，不为文案调整启动长训练或全平台审计。

## 开始任务

1. 读取适用 `AGENTS.md`；编辑前检查 `git status --short`、`git branch --show-current`、`git remote -v` 及目标 diff。保护未提交修改、未跟踪源码、平台适配和冻结证据。多步骤仓库改动使用合适的 `codex/` 分支；优先复用可安全使用的 checkout。
2. 用 [项目入口与规则验证](references/project-map.md) 定位相关源码、规范和测试。跨工作树任务再查当前挂载工件、`git worktree list` 和对应聊天的只读状态；不把历史路径、PID、报告 PASS 或其他聊天的计划当现场事实。
3. 固定触发场景、预期行为、规则版本、目标平台/模式和验收方式。缺信息会改变规则、数据或必要外部动作时才询问，期间继续独立工作。
4. 有其他任务同时发布同一目标时先确认发布归属和候选覆盖，避免并行切换。可只读了解其他聊天；发指令、接管发布或改变其工作仍需相应授权。

## 仓库、指南和全平台整理

- 仓库正式资料位于 `working/docs/` 与 `working/task/`；平台 `project/` 是独立工作树入口。整理时读取实际目标，保留冻结证据和恢复路径。只改变目录导航不能称代码整合；默认分支、主工作区、线上与安装包分别查证。
- 用户要求“以网页和小游戏为准”时，以两端已完成且可验证能力的并集形成候选，再保留各目标端既有产品能力和宿主适配；先查后续修复与功能差异，不能退回日期较早的统一包。常规与拓扑的人数、规则和 AI 适用范围分别核实。
- 指南舱从实际 Guide 模块和生成器定位，维护唯一正文和旧锚点；内容、生成文章与阅读界面一起验收，中英文、手机、长公式和代码均需可读。
- 大范围整理先形成问题清单、来源/能力矩阵、依赖顺序和验收计划。用户要求完整提示词时交付可继续执行的文本；要求实施时持续完成工程。按当前授权使用子 agent，并预先分配文件职责及共享文件边界。
- 更新本技能时优先维护仓库 `working/skills/lifeline-dev/` 的可审阅源码，再验证并同步到已安装技能；仅交仓库副本不能称安装完成。仓库副本不存在时先建立完整来源副本，避免漏掉引用或覆盖其他技能。

## 不可丢失的契约

- **规则显式版本化。** 2026-10-25 的主树源码快照为新局默认 `territory-v3`、裸 `new GameEngine()` 默认 v1；仅作定位线索，每次沿所选 checkout 的调用链核实，不代表线上状态。新建、退出旧房间后重开不能继承旧规则；旧存档、棋谱和房间按所存版本恢复。保留旧版本兼容，不改写冻结研究环境。
- **正式分数用离散 `area`。** v3 的己方节点/线点始终计分，另加不含敌方元素的封闭空腔；单线、开链、多空腔和甜甜圈适用。几何 `displayArea`、填色轮廓和 AI 估值不能替代比分、赢家或终局。详见项目地图的 v3 契约。
- **完整状态才决定规则。** 保留棋盘形状、完整起点/永久根集、行动顺序、逻辑边、行动方、`historyHashes`/Superko、PASS、认输、终局及版本；拓扑还携带规范定义、接缝和定义哈希。悔棋、缓存、搜索、跨端重放不能只复制占点；不同历史的同盘面不等价。
- **异步结果属于当前请求。** 复用 `AIStateProtocol.js` 和现有 Worker/session，核对 request ID、引擎身份、position revision、规则版本和行动方。重开、悔棋、重连、设置变化后拒绝旧结果，执行前再验合法性。
- **分析和导入保护当前对局。** 隔离搜索与检查状态，异常也恢复；棋谱先在隔离引擎校验再替换。公开棋谱、持久存档和临时 Worker 快照分别遵守各自契约。
- **训练沿合格教师入口。** 新产品标签使用 `DefensiveTrainingTeacher.js` 与 `defensive-training-data-v1.mjs`，核实实际完成的 Minimax 深度/对手行动轮数、全合法根含 PASS 及精确根值；预算不足不出标签。旧冻结数据不能静默重标，训练/强度/产品准入分开。
- **提速保留用户指定的结果和能力。** 区分规则计算、几何生成、绘制、Worker 通信和 AI 搜索；减少重复工作与精确剪枝优先。降低深度/候选预算、换启发式或近似着色属于质量权衡，不能冒充等效优化。

## 验证与交付

先跑受影响模块的现有回归。规则 bug 保留最小反例；同步检查源文件、依赖、构建产物与实际入口；性能比较相同输入、版本和预算。相关检查通过后，仅因新变化、失败或未决风险扩大测试。

Node/mock、静态验包、进程存活、HTTP 200 和资源哈希各有用途，不能替代浏览器交互、微信运行环境、真机或跨端联机。按当前任务验证实际用户路径；未具备的环境明确列出。

源码、测试、配置、文档和紧凑证据按仓库约定纳入版本控制；原始轨迹、检查点、日志、数据库、凭据及生成大包留在本地。仅提交本任务文件；推送前审阅暂存 diff、凭据与大文件并运行相关检查，不改写共享历史。

用简洁中文先报结果与可点击的绝对路径，再说变化、验证范围和剩余步骤。多平台逐项报告代码整合、构建、设备、上传、体验版、服务激活、审核和公开状态；使用现有收据定义的状态，不因某端通过就宣称全部同步上线。调用技能不自动授予推送、部署、上传、付费、签约或重启其他任务的权限；本会话已经授权的动作继续执行。
