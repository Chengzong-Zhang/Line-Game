# 研究实验、模型接入与可靠运行

仅在任务涉及研究、训练/评估、模型接入、长任务恢复或正式结果时读取。本文件约束工作方法，不宣布任何既有实验的当前状态，也不把旧任务的预算授权延续给新任务。

## 查找当前契约

仓库路径相对用户选定的 checkout：

- 研究环境和入口：`research/iclr2027/README.md`、`ENVIRONMENT.md`、`pyproject.toml`。
- 研究范围与主张：`research/iclr2027/D1_research_contract.md`、当前任务专属协议以及相应 claim/evidence/limitation 文档。历史 D17/D19/D20 编号只用于定位，不代表当前任务或已完成状态。
- 工件边界：`research/README.md`、`research/iclr2027/results/README.md` 和任务专用 artifact policy。规则冲突时保留冻结文件并厘清当前范围，不就地改写历史证据。
- 尺寸迁移的计划入口：`research/iclr2027/experiments/size_transfer_v1/EXPERIMENT_PLAN.md`、`AI_EXECUTION_PROMPT.md`、`VALIDATION.md`；预算取当前校准和本次授权，不照抄旧预算。
- 尺寸迁移实现入口：`research/iclr2027/scripts/size_transfer_draft.py`、`size_transfer_runner.py`、`size_transfer_campaign.py`；恢复测试是 `research/iclr2027/tests/test_size_transfer_runner.py`，准备阶段测试是 `test_size_transfer_draft.py`。

先检查实际 CLI、配置、receipt schema 与测试，再确定命令。目录名有 runner、supervisor 或 validation 不意味着已经通过恢复门。

## 定义可回答的问题

先固定假设/比较对象、规则与 observation/action 契约、模型来源、尺寸、seed、对手、搜索/训练预算、终止和截断处理、统计单位与验收标准，再实现或执行。复用适用的冻结协议；需要改变设计时另建版本，记录差异与适用范围。已被用户或协议永久关闭的路线保留关闭决定，不通过更换 ID、改预期或改名绕过；普通新版本不是重开授权。

- 区分应用表现、算法变化、规则变化和研究主张；不同规则或预算的比较要明确标注。
- 对局数量、独立训练 seed 和同一模型的重复对局是不同统计单位。胜率给分母、先后手、对手与不确定性；只有在结论需要时进行相应统计，不把同一模型的每步当独立训练证据。
- Superko 的历史依赖不能因为 pilot 中出现较少就被删除。主张“相同观察，不同历史”时核对观察中的 legal mask/history digest，避免把接口差异当纯历史消融。
- `zero_shot`、`scratch_all`、`transfer_all`、`transfer_curriculum` 分开记录。目标尺寸上继续训练后的表现不能称零样本外推；尺寸推理 probe 通过不能称棋力提升。

## 模型进入浏览器

先检查当前导出器、模型 manifest、权重与来源哈希；相关入口为 `research/iclr2027/scripts/export_web_research_models.py`、`export_web_model_free.py` 和前端模型适配器。已有资产足够时不为接入功能重训模型。

旧研究动作常为三角棋盘 row-major 编号的 `n(n+1)/2` 个点加最后一个 PASS；其他形状和多人模型按各自 manifest 核验，不能套用这个数量。桥接时核对坐标、视角、关系顺序、padding、合法 mask、主动 PASS/自动 skip、终局、规则版本、人数、起点与尺寸范围。

使用冻结输入验证数值有限、合法先验归一化、动作映射、完整状态恢复与输出来源。初始化局面的数值 parity 仅支持相应输入，不等于全局规则等价。v1/v2 训练模型在 v3 引擎下合法运行，只能按证据称兼容试验；规则、计分、人数、棋盘形状或起点改变后，需要针对目标场景重新核验，未经匹配评估不能升级为新规则棋力或论文结果。

多人四档和产品准入还须遵守 [AI 与性能](ai-performance.md)：训练完成、数值检查或能加载不能代替强度验证；未准入的终极候选保持隔离。导出、Worker bundle、模型 manifest 和各平台资源清单绑定同一来源，跨端构建见 [多平台同步](platform-sync.md)。

载入失败、hash/schema 不符、非法动作或超时要保留棋局并明确告知降级。研究分数、prior、Q、visits、训练 loss 均按实际含义展示；不得当作真实胜率、最佳走法证明或模型冠军依据。

## 新长任务启动前

长训练和长评估必须先有以下可核对实现与验证。这是仓库所有者的可靠性要求，来自根目录 `AGENTS.md` 的 Long-running experiment reliability 部分；没有通过时继续补实现和做有界恢复测试，不以“先跑起来”替代。

1. **持久状态与 resume。** checkpoint 保存恢复所需的模型、optimizer、适用的 scheduler、replay、计数器、CPU/GPU RNG 和任务进度；在途单元有可重建状态或明确的未提交边界。临时写入经校验后原子替换，索引只指向有效状态；绑定源代码、配置和父 checkpoint 身份。
2. **增量评估。** 对完成的 game/task 等单元使用稳定 ID、持久结果与幂等收据。恢复读取已验证的完成集合，不重训已完成模型、不重跑已完成对局；保留并隔离不完整的尾部写入。
3. **独立监督。** 无人值守任务由独立于本终端/聊天的监督者运行，记录命令、退出码、重试次数、进度与时间；根据任务需要安排登录后恢复。单纯后台启动一个 worker 不等于有监督。
4. **防重复与暂停/停止。** 运行目录独占锁或等效互斥关联明确的进程身份。提供 PAUSE/STOP 或等效控制及确认收据；用户已暂停的任务不能被恢复器重新拉起。操作锁前核对实际命令行、run root 和 supervisor，不能只看 PID 是否存在。
5. **有界自动恢复。** 意外退出可从验证后的状态重试；限制无进展重试次数并保留故障证据。源/配置变化、身份不匹配、收据或 checkpoint 损坏时停止，不通过改 hash、删证据或放宽校验继续。
6. **中断演练。** 用独立、低成本目录验证提交前后故障、半写入、重复启动、正常恢复、监督重启、暂停/停止和损坏拒绝。比较恢复与干净运行的完成单元、计数器及协议要求的状态；保证没有重复或遗漏。
7. **预算和范围。** 从代表性棋盘/配置的实测估算时间、内存、磁盘和训练/对局量，写出截断与成本上限。正式启动必须落在用户已授权的范围内；小盘吞吐不能直接外推大盘，也不能因具备云工具就自动购买算力。

`py_compile`、初始化成功、若干 inference probes 或日志末尾一个 `OK` 不能替代这些检查。查看实际命令和退出码。恢复测试尽量用确定性轻量 fixture，真实训练/强度评估另行执行，避免把恢复单测变成大规模自对弈。

## 恢复、迁移与现场核查

**同实验 resume** 严格恢复协议所需全状态并校验身份；**weights-only 迁移** 是新实验，沿用权重但按新协议重置 optimizer、replay、计数器和 RNG，保留父 checkpoint 来源。不要用迁移绕过 resume 不匹配。

遇到“还在跑吗”“继续任务”时，读取任务专属状态、最新有效 checkpoint、完成单元和 supervisor 记录，并核对进程命令行与路径。旧 PID、初始化 receipt 或文件更新时间不足以证明仍有进展；查看持久单元增长。继续工作前遵守现有 PAUSE/STOP 和会话授权，不在不清楚归属时杀进程、删锁或启动重复 worker。

恢复入口、暂停/停止入口及其作用范围都写进任务记录。长任务的进度依据持久事务/评估收据，不用“进程已重启”冒充任务完成。固定协议正在使用的源码不能静默改动；修复应生成可追踪的新版本并使用协议允许的恢复/迁移路径。

## 完成与发布判定

按任务分别报告：训练进度、评估进度、恢复验证、独立校验和发布状态。完成率必须给已完成单元/计划单元及口径；存在阻断时写明缺少哪份证据，保留其他已完成成果。

正式结果需要本任务规定的完成收据、聚合表、源/配置/工件 hash 和独立 verifier 的确切命令、退出码与报告。`formal_ready` 按该 verifier 的定义解释，不能代表产品发布、结论普适成立或论文接收。独立脚本校验也不等于外部审稿或另一位研究者独立复现。

smoke、pilot 与 formal 产物使用各自目录和标签。紧凑的协议、聚合数据、结果说明、receipt、hash 和验证报告可纳入版本控制；大检查点、原始轨迹、完整执行树和日志保持本地。既有正式结果不覆盖，修正以新版本或附加说明保留来源链。
