# 拓扑棋盘与完整状态

仅在拓扑、多起点、顺序、图形编辑、3D 或跨端状态相关任务读取。模块名字是定位线索，必须沿当前入口确认。

## 定位与规则边界

优先找 `BoardDefinition.js`、`BoardTopology.js`、`BoardPaths.js`、`BoardEditor.js`、`BoardView.js`、`TopologyGameEngine.js`、`TopologyStateProtocol.js`、`TopologyReplayCodec.js`、`TopologyRegion*.js`、`TopologySurface*.js` 及对应测试。

普通三角/六边/菱形与任意拓扑可能有不同人数、尺寸、规则版本和 AI 路由。用实际新局入口判定，不能把普通棋盘人数上限套给拓扑。曲面并非普通边界矩形的视觉变形：规范顶点、接缝配对、方向搬运、极点和路径都参与规则。

拓扑计分和区域需依当前实现的链复形、F₂ 区域或根证书契约核查；常规 territory-v3 的外边界泛洪不能直接证明闭合曲面结果。理论、实现与有限反例分别说明，不把可视轮廓或 3D 面片当正式比分。

## 不可缩减的状态与兼容

- 保留规范棋盘定义、定义/规则哈希、接缝方向、完整永久起点/根集、逻辑边、行动顺序、当前方、Superko 历史、PASS/认输及终局。房间、存档、棋谱、AI/提示 Worker 都需携带适用字段。
- 自定义图形可能有多个边界/孔洞；预览、校验、提交和重置使用同一规范化路径。编辑草稿不得直接替换正在进行的对局，非法/失败导入不损伤旧局。
- 多起点连通性沿显式逻辑边追溯完整根集，不以视觉相邻或旧角点判断。新增起点、迁移/旧模式、行动顺序在旧存档中的兼容依据实际版本，不静默重解释。
- 用户取消独立设置模式时可合并入口，不能因此删除旧存档读取。普通和拓扑的认输、重置、保存、悔棋与计时行为应沿产品语义对齐。
- 先手变成任意行动顺序时，修改引擎循环、AI执行、终局、协议和序列化；只调整颜色按钮顺序不是功能完成。跳过已认输/退出席位、重复/非法顺序及旧字段回退需要固定例。

## 渲染、3D 与平台

逻辑规范点、平面 atlas 副本、渲染像素和 3D 投影是不同坐标空间。接缝路径按方向搬运选择正确副本，检查长斜线、首段丢失、圆柱方向反转和极点。不能用画面连续掩盖逻辑错连，也不能为省帧率改变规则路径。

3D 展示应复用同一棋盘/状态身份，关注隐藏/切页暂停、前后台、触摸旋转和缓存失效。性能报告固定同一场景，分开几何生成、软件绘制、通信与规则；降低质量明确为权衡。

微信需原生 Canvas/API/Worker 适配及真实分包依赖，保留旧 Android 正则解析兼容修复；Web 的 DOM 或浏览器截图不证明微信真机可用。构建时追踪新增嵌套 Worker、`.mjs` 与动态依赖，旧宿主浅层复制不能当全量同步。

## 验证选择

用 `rg --files web/web前端/tests` 与平台 tests 定位现有 topology/turn-order/multi-start/region/roots/surface 测试，读取后选择与改动对应的固定反例。覆盖规范定义/哈希、接缝与方向、计分、起点/顺序、保存重放、AI过期结果、重置及房间恢复；涉及UI还需实际操作。

跨实现固定相同版本、定义、完整根集、顺序与动作，逐步比规则状态和正式得分；revision、缓存和投影不必字节相等。真实双客户端/跨端房间、设备3D与包内资源各自报告，不用单模块测试概括全平台。
