## 用户目标与范围

当前工作树 `C:/Users/zcz/.codex/worktrees/wechat-topology-fix-20261030/line game`，本轮起点 `7dc00a1d`；新分支 `codex/wechat-board-flow-20261030`。沿用已修复的 0.13.1：原生 UTF-8、完整拓扑、领土填色、随机/多根、原生头像滚动、v4 棋谱上传和较长拓扑校验优化都必须保留。主要改微信小游戏的实际 UI；多边界编辑语义以当前 Web BoardEditor 为准，真实行动顺序涉及共享核心、存档、棋谱、Worker 和联机合同，不能只改显示。

用户七项原意：

1. 拓扑与普通棋盘用同一对局界面，均有认输、重置。点击一种拓扑预设即保存选择和高亮，离开面板/重新启动后仍能恢复。取消独立“开始拓扑对局”；统一“重置”按当前已保存的下一局地图/起点/顺序配置开局。选择地图不破坏正在进行的棋局。
2. 取消“经典模式、固定双起点、迁移起点”三个独立模式入口。保留旧存档、棋谱和恢复的规则版本。把“自定义棋盘”和“自定义起点”合并为一个图形编辑器，在一个工作区画轮廓、粘边、选择颜色并放置/删除起点。用户未要求删除“增设起点”的对局能力，不擅自丢掉；可保留独立开关或在编辑器里清楚配置。旧经典语义可作为默认规则内部实现，不继续要求玩家选择“经典模式”。
3. “随机地图”和“自定义棋盘”是棋盘面板直接可见按钮。点击“拓扑棋盘”只在原面板展开更多预设图形，不进入新的拓扑设置页面，不把形状选择和开始对局放到二级流程。再次点击可折叠，已选高亮不丢。
4. 自定义棋盘与 Web 对齐：支持多个边界、孔洞或多个轮廓；新增/选择/删除轮廓、关闭轮廓、撤销、粘边与方向、各方起点均尽量点图操作。不能只给边或顶点 ID 列表让用户输入，也不能仅支持一个外圈。已有有效草稿在非法编辑后保留，错误定位可见。完成编辑是“保存配置”，应用仍统一走重置。
5. 悔棋、计时、提示各占一行，左侧开关、右侧数值输入。悔棋/提示是次数，计时是秒数；直接聚焦同一行的输入区域，使用原生键盘，不能 showModal/showActionSheet 输入或另弹设置页。支持输入、删除、失焦校验；禁用时数值保留，切页/滚动/后台关闭键盘并拒绝旧回调。数值范围沿既有 normalizePlayOptions，不悄悄放宽规则。
6. “先手设置”变为“顺序设置”。默认 1、2、3、4……；每方用自己的颜色做拖动块并显示序号，拖动改变实际循环行动顺序，不只是把某一方改为先手或移动文案。身份/颜色、控制器、起点归属保持对应。人数变更保留仍在场玩家的相对顺序，新玩家追加；非法或重复顺序拒绝，不能静默执行另一种顺序。新顺序只对下一局/房间提交生效，当前局继续。旧存档没有新字段时按原先手与原循环恢复。
7. 进一步优化 3D。比较相同地图、视角、尺寸和像素输出；先查每帧模型构造、内存分配、投影/颜色解析、三角形光栅化、无变化时重绘和自动旋转调度。优先缓存、复用 buffer、精确裁剪/增量计算。不得通过删去地图、起点、线、领土、遮挡或任意降低画质冒充优化；若自适应分辨率涉及质量权衡要明确。保留旋转、缩放、暂停、返回及资源释放。

## 交互方案与状态边界

棋盘面板按：参与者/顺序 → 四类棋盘按钮 → 展开的拓扑图形 → 随机地图/自定义棋盘 → 边长与地图预览 → 必要起点快捷配置 → 三行开关/输入。保留现有语言、显示、贡献、复盘及房间入口，避免无关重排或重写整套应用。

地图选择保存的是“下一局配置”。统一重置使用该配置；进行中的普通/拓扑局仍使用自己的完整 settings，不因面板切换而改变 boardHash。草稿改变后，旧预览、异步 picker、输入法和 AI 结果按 generation/session/epoch/visibility 失效。重置确认之后才取消旧 Worker、替换 session；取消则棋局不变。

统一自定义编辑器支持两种来源：普通三形状可先载入该形状再编辑起点；任意拓扑/多边界用编译定义和 canonical 顶点。编辑工具为“轮廓/接缝/起点”，仅编辑器可以有独立工作区，拓扑预设列表不能再单开新页面。保存返回原棋盘面板；编辑取消丢弃本次未保存更改，已保存配置不变。

原生数字键盘只是输入手段：行内绘制文本/光标和选中状态，焦点始终属于同一行。回调必须有 token，并校验 scene/cabin/设置对象，滚动、切页、后台或销毁后不得写入新设置。空值编辑中允许存在，提交时恢复上个有效值或显示行内错误，不能把空字符串变成 0 或 NaN。

顺序是规则输入，应显式存入新局配置并进入状态/hash。不得把“调换玩家 ID/颜色”当作调换行动次序。保存、悔棋、AI、提示、自动跳过、认输、终局、复盘、导入导出、贡献、联机应保持同一顺序。遇到旧协议不能表达任意顺序时应扩展协议并同步服务，不能 UI 接受而后台静默改回默认。
