## 2. 教学运行契约

### 2.1 规则版本与坐标

四关统一使用一份可复现的 Web 引擎配置：

```js
{
  gridSize: 6,
  playerCount: 2,
  startPlayer: "BLACK",
  rulesVersion: "territory-v2"
}
```

坐标使用引擎坐标 `[x, y]`，有效点满足 `x >= 0`、`y >= 0`、`x + y < 6`。默认起点为：

```text
BLACK = [0, 0]
WHITE = [5, 0]
```

教学不可直接写入 `grid`、`edges` 或 `historyHashes`。每关必须：

1. 创建新的 `GameEngine`；
2. 按 `prefix` 顺序调用真实的 `playMove` / `skipTurn`，检查每一步 `success === true`；
3. 只把学生的动作提交给同一引擎，或先在隔离副本/`replayBatch` 中试算；
4. 以引擎快照中的 `boardMatrix`、`edges`、`territories`、`currentPlayer`、`gameOver`、`winner` 和 `consecutiveSkips` 判定成功。

如果前缀回放失败、规则版本不支持或断言不匹配，教学必须 fail closed，显示“教学场景与当前规则版本不兼容”，不能以静态动画冒充完成。

### 2.2 关卡配置格式

实现时建议使用如下数据结构；这是规格契约，不是当前已有 API：

```js
{
  id: "L1-connect",
  engine: { gridSize: 6, playerCount: 2, startPlayer: "BLACK", rulesVersion: "territory-v2" },
  prefix: [
    // { type: "move", player: "BLACK", point: [1, 0] }
    // { type: "skip", player: "WHITE" }
  ],
  objective: { type: "move", player: "BLACK", point: [1, 0] },
  success: { /* read-only snapshot assertions */ },
  retryPolicy: "restore-prefix"
}
```

`player` 用于校验当前轮次，不可由 UI 自行切换。教学的“目标动作”与“引擎合法动作”分开：一个动作可以合法但不符合本关目标；此时使用隔离副本试算并恢复教学局面，不能污染学生当前关卡。

## 3. 四个真实引擎教学关卡

### L1：先把生命线接出去（连接与扩张）

**教学句子：**“新节点必须和自己的起点连上；先把蓝方的生命线向外延伸一步。”

| 项目 | 配置/要求 |
|---|---|
| 关卡 ID | `L1-connect` |
| 初始配置 | 上述统一引擎配置；`prefix = []`；当前轮为 `BLACK`。棋盘只有黑 `[0,0]`、白 `[5,0]` 两个初始节点。 |
| 目标动作 | 黑方落子 `[1,0]`。该点与 `[0,0]` 同一水平线，且不在白方起点保护区。 |
| 学习目标 | 理解同色节点间会生成线；落子必须与自己的结构连通。 |
| 成功条件 | `playMove([1,0]).success === true`；`boardMatrix[0][1] === PointState.BLACK_NODE`；黑方 `edges` 包含 `0,0|1,0`；`turnCount === 1` 且当前轮转为白方。 |
| 当前验证结果 | 按当前 `GameEngine` 回放成功；黑边为 `0,0|1,0`，领土仍为 0。 |
| 目标反馈 | 目标点出现“已连接”状态，边从起点到新节点短暂高亮；正文说明“线是补给/连通关系，不是额外棋子”。 |
| 失败提示 | 非法点：`“这一步没有改变棋局。请在自己的生命线能连到的位置落子。”`；合法但非目标点：`“这一步可以走，但本关只练习第一次连接。请点亮的 [1,0]。”` |

### L2：围出第一块领土（闭合与领土）

**教学句子：**“三条同色边围成闭合区域后，引擎才会计算领土。”

| 项目 | 配置/要求 |
|---|---|
| 关卡 ID | `L2-close-territory` |
| 初始配置 | 统一引擎配置；前缀依次为：`BLACK move [3,0]`，`WHITE skip`。回放后当前轮为黑方，黑方已有从 `[0,0]` 到 `[3,0]` 的边，`consecutiveSkips === 0`。 |
| 目标动作 | 黑方落子 `[0,3]`。它会同时连接 `[0,0]` 与 `[3,0]`，形成闭合三角边界。 |
| 学习目标 | 理解闭合边界与领土分数的关系，区分“有线”与“已闭合”。 |
| 成功条件 | `playMove([0,3]).success === true`；黑方 `edges` 恰好包含 `0,0|3,0`、`0,0|0,3`、`0,3|3,0`；黑方 `territories.BLACK.polygon !== null` 且 `territories.BLACK.area > 0`。 |
| 当前验证结果 | 按当前 `territory-v2` 实现，`area === 10`、`displayArea === 9`；胜负应使用 `area`，展示几何面积不能替代规则分数。 |
| 目标反馈 | 先显示第三条边，再填充黑方领土；分数区从 0 变为引擎快照的 `area`。不写死“内部只有一个点”。 |
| 失败提示 | 非法点：`“这一步没有改变棋局。请先完成能闭合三条边的目标落点。”`；合法但非目标点：`“这一步还没有完成本关的闭合。请尝试高亮的 [0,3]。”`；三点限制触发时：`“三个节点不能主动挤成最小三角；只有直接切断时才例外。”` |

### L3：切断补给线（切断与断联清除）

**教学句子：**“切断不是吃掉一个点；失去起点连通性的敌方部分会一起断联清除。”

| 项目 | 配置/要求 |
|---|---|
| 关卡 ID | `L3-cut-and-clear` |
| 初始配置 | 统一引擎配置；前缀依次为：`BLACK move [3,0]`，`WHITE move [2,3]`。回放后白方有边 `[5,0]`–`[2,3]`，中间线点包括 `[4,1]`、`[3,2]`；当前轮为黑方。 |
| 目标动作 | 黑方落子 `[3,2]`，正好落在白方线段上，并可与黑方节点 `[3,0]` 连通。 |
| 学习目标 | 观察攻击点、被切边、断联节点和线的因果顺序。 |
| 成功条件 | `playMove([3,2]).success === true`；`boardMatrix[2][3] === PointState.BLACK_NODE`；白方 `[2,3]` 和 `[4,1]` 均为空；`edges.WHITE` 不再包含被切断的边；当前轮转为白方。 |
| 当前验证结果 | 按当前引擎，白方 `[2,3]` 与 `[4,1]` 被清除，黑方 `[3,2]` 成为节点，黑边包含 `3,0|3,2`。 |
| 目标反馈 | 建议事件顺序为：①被点击的白线变为“断点”；②边界闪烁/变色；③白方失去起点连通性的节点和线淡出；④文字说明“断联清除”。这组动画是待实现的表现层，不是当前 Renderer 已有能力。 |
| 失败提示 | 落在空点或非敌线：`“切断必须落在敌方的线上；空点不能触发切断。”`；点 `[4,1]`：`“这里靠近白方起点，属于保护区。请观察更远的白色线段 [3,2]。”`；合法但非目标点：`“这一步没有切断本关的生命线。请点亮白色线段上的 [3,2]。”` |

### L4：让引擎结算（跳过与终局分数）

**教学句子：**“领土由引擎结算；连续跳过达到规则条件后，棋局才进入终局。”

这里刻意使用已闭合的 L2 局面，避免把“结算”误教成“再随便围一个圈”。本关的终局触发是固定前缀加一次学生跳过，不应文案化为“没有合法点才结束”。

| 项目 | 配置/要求 |
|---|---|
| 关卡 ID | `L4-settle-score` |
| 初始配置 | 统一引擎配置；前缀依次为：`BLACK move [3,0]`、`WHITE skip`、`BLACK move [0,3]`、`WHITE skip`。回放后已有黑方闭合领土，当前轮为黑方，`consecutiveSkips === 1`。 |
| 目标动作 | 点击“跳过回合”一次，调用真实 `skipTurn()`。 |
| 学习目标 | 理解连续跳过、终局、`area` 分数和 `winner` 的关系。 |
| 成功条件 | `skipTurn().success === true`；`gameOver === true`；`winner === Player.BLACK`；`consecutiveSkips === 2`；黑方 `area > WHITE.area`。 |
| 当前验证结果 | 按当前引擎得到 `gameOver: true`、`winner: BLACK`、黑方 `area: 10`、白方 `area: 0`。 |
| 目标反馈 | 显示“本关结束”，逐项读出终局原因、黑白 `area` 和获胜方；允许“重玩本关”和“进入第一局”，不自动跳转联机房间。 |
| 失败提示 | 点击棋盘：`“本关现在练习结算，请使用‘跳过回合’。”`；重复操作：`“本关已经结束。可以重玩，或进入第一局。”` |

## 4. 首次对局流程

### 4.1 首次进入

**待实现入口：**在现有 `Guide` 入口旁增加明确的“第一次玩 / Play tutorial”按钮；不要把四关藏在已有静态规则弹窗的三个阅读版本中。

1. 首屏只说明三件事：同色节点连成生命线、切断会清除断联部分、闭合区域才计领土。
2. 提供“开始教学”和“直接开始本地对局”两个选择；首局不要求登录、不要求连接服务器。
3. 创建上述固定教学引擎，显示当前关卡、一个目标、一个“重玩本关”按钮和一个“跳过教学”按钮。
4. 每关只提交一个核心动作。成功后显示引擎事件解释，再由用户点击“下一关”；不使用自动倒计时。
5. 教学完成后询问“现在开始第一局吗？”：默认进入本地双人/AI 设置，明确显示规则版本与棋盘尺寸；不得把当前仓库的默认 9 边长改写成“新手默认 6”。6 边长只属于本规格的可验证教学夹具。
6. 如果选择 AI，沿用现有 2 人本地 AI 入口和实际可用深度；如果未选择 AI，进入本地轮流模式。AI 是否可用、加载和等待状态仍由现有 UI 实际状态决定。

### 4.2 每关的固定屏幕结构

```text
[第 2/4 关]  围出第一块领土
目标：完成黑色闭合边界
提示：点击高亮点 [0,3]

                 三角棋盘

[重玩本关] [跳过教学]                         [下一关]
[状态 live region：等待你的动作 / 已完成 / 失败原因]
```

目标点、高亮说明和文本坐标必须同时存在；不能只靠颜色、动画或坐标悬浮提示。教学 UI 的目标落点可以比普通局面更突出，但底层判定始终来自真实引擎。

### 4.3 状态保存边界

本规格不把本地自动保存、刷新恢复或棋谱导入导出冒充为现有 v0.1 教学能力。若后续加入保存，至少保存 `levelId`、引擎配置、完整合法前缀、已确认教学动作、`rulesVersion` 和构建标识；损坏或版本不兼容时回到关卡起点并告知用户。

## 5. 切断、非法动作与反馈契约

### 5.1 反馈分层

| 情况 | 引擎事实 | 用户反馈要求 |
|---|---|---|
| 点击非棋盘点 | Controller 可能返回 `MISS` | 不改变局面；在棋盘旁提示“请点在棋盘节点附近”，移动端可显示短暂命中圈。 |
| 非法落子 | 当前 `GameEngine.playMove` 返回 `INVALID_MOVE`，不会提交变化 | 教学适配层补充原因；提示原因、相关点和下一步动作；不增加回合数。 |
| Superko | 引擎返回 `SUPERKO_VIOLATION` 并回滚 | 明确“会恢复历史局面，禁止重复”；显示“本次尝试未改变棋局”。不在四个基础关强行要求用户触发。 |
| 轮次/联机锁定 | Controller 有 `NOT_YOUR_TURN`、`ROOM_NOT_READY`、`OPPONENT_OFFLINE` 等锁定原因 | 保留当前棋盘，说明等待对象；不把联机锁定误报为规则非法。 |
| 教学中合法但非目标 | 规则允许，教学目标不允许 | 用隔离副本试算后恢复关卡，提示“这一步合法，但不是本关目标”；不能让学生因探索合法点而丢失关卡进度。 |
| 已结束 | 引擎返回 `GAME_OVER` | 禁止继续落子，展示终局面板；提供重玩或离开。 |

### 5.2 原因诊断要求

当前公开提交接口不足以区分保护区、三点限制、未连通和占用节点；实现教学时新增的诊断层必须满足以下顺序：

1. 先检查坐标是否有效、是否已结束、是否轮到该玩家；
2. 在隔离引擎上试算候选动作；
3. 若失败，依据规则前置检查和真实试算给出一个稳定原因码；
4. 再用 `getLegalMoves`/快照确认该动作没有被错误标为合法；
5. 只有成功的目标动作才提交到教学主引擎。

建议原因码：`MISS`、`OUTSIDE_GRID`、`GAME_OVER`、`NOT_YOUR_TURN`、`OCCUPIED_NODE`、`PROTECTION_ZONE`、`THREE_POINT_LIMIT`、`NOT_CONNECTED`、`LINE_BLOCKED`、`SUPERKO_VIOLATION`、`TUTORIAL_TARGET_MISMATCH`。原因码是待实现的教学协议，不是声称当前 `GameEngine.playMove` 已全部返回这些值。

### 5.3 切断事件的可读反馈

切断成功后，状态播报至少包含：

```text
黑方落在白方线段 [3,2]。
白方边 [5,0]—[2,3] 被切断。
白方 [2,3] 失去与起点 [5,0] 的连通性，已清除。
```

实际显示应从快照差异计算，不从坐标文案硬编码清除结果。若一次攻击没有清除棋子，也应说“线被切断，但没有断联棋子被清除”，不能固定播放“消灭一片”。动画默认短、可跳过；减少动态效果时仍保留顺序和文字。

## 6. 移动端与无障碍最低要求

### 6.1 移动端最低要求

- 支持手机竖屏，内容宽度 320 CSS px 起不横向溢出；窄屏下棋盘、目标说明、失败提示和主操作都可见。
- 节点的可点击/触摸有效区域至少达到 44×44 CSS px；若棋盘缩放后节点间距无法满足，采用“点选后确认”或缩放/平移，不靠更小的命中阈值解决。
- 保留单指点击，不要求悬停；不使用双指手势作为唯一操作。现有 `touch-action: manipulation` 可作为基础，但不能替代确认与误触恢复。
- 目标点和非法点反馈在 1 次触摸后 100 ms 内出现可见状态；动画期间不阻塞“重玩本关”和“跳过教学”。
- 控件在 320–430 px 宽度下不重叠；主按钮触控高度至少 44 px；底部操作不被安全区域或系统键盘遮挡。
- 支持 `prefers-reduced-motion: reduce`：切断动画改为即时状态变化，保留颜色之外的轮廓、文本和 live region。

当前 `Renderer` 已做 DPR/ResizeObserver/响应式 Canvas 适配，当前 CSS 已有 640 px 与 coarse pointer 分支；这些是基础能力，不等于以上验收已经通过。

### 6.2 键盘和读屏最低要求

- Canvas 旁提供隐藏视觉但可读屏、或可见的语义化落点列表；每个教学目标点至少有一个 `<button>`，带坐标/动作名称和 `aria-pressed` 或明确选中状态。不能要求用户用键盘操作 Canvas 像素。
- Tab 顺序固定为：关卡标题/目标 → 棋盘可操作入口 → 重玩 → 跳过 → 下一步/进入对局。弹窗打开后焦点进入弹窗，关闭后回到原按钮；Escape 可关闭非必要阅读弹窗。
- `role="status" aria-live="polite"` 播报当前轮、目标、成功和正常状态；`role="alert"` 播报非法动作、版本不兼容和需要用户立即处理的错误。避免同一事件重复播报。
- 当前玩家不能只由蓝/红/紫颜色表达；同时显示文字、形状/轮廓或图标。切断前后的节点变化要有文本说明。
- 所有焦点可见，文字放大到 200% 时仍可完成四关；颜色对比、按钮禁用态和错误态不能只靠透明度差异。
- 读屏文本必须读出：关卡号、目标、当前玩家、目标坐标、成功条件、失败原因和下一步。`canvas aria-label` 只能作为补充，不能作为完整棋盘操作接口。

## 7. 验收用例

以下是 v0.1 的验收集合。除特别注明外，均使用真实 Web `GameEngine`，禁止用 mock 的“成功动画”代替规则断言。

### 7.1 引擎与关卡一致性

| ID | 操作 | 必须通过 |
|---|---|---|
| T-01 | 为每个关卡创建新引擎并逐条回放 `prefix`。 | 所有前缀动作成功；配置为 6/2/BLACK/`territory-v2`；失败则关卡不可开始。 |
| T-02 | 回放后检查当前玩家和关键局面，再执行目标动作。 | L1 当前黑、L2 当前黑、L3 当前黑、L4 当前黑；目标动作均 `success === true`。 |
| T-03 | L1 读快照。 | 黑边含 `0,0|1,0`，回合数为 1，领土为 0。 |
| T-04 | L2 读快照。 | 黑边形成三条闭合边，黑 `polygon !== null`，黑 `area > 0`；当前实现的 `area/displayArea` 分别与规则版本记录一致。 |
| T-05 | L3 比较攻击前后快照。 | 白 `[2,3]` 和 `[4,1]` 从占用变为空，黑 `[3,2]` 为节点，白被切边不再存活。 |
| T-06 | L4 执行一次真实 `skipTurn()`。 | `gameOver === true`、`winner === BLACK`、连续跳过为 2，胜者由 `area` 而非展示面积计算。 |
| T-07 | 改动任一前缀动作或规则版本。 | 关卡断言失败时显示不兼容，不允许以成功动画放行。 |

### 7.2 非法动作和切断反馈

| ID | 操作 | 必须通过 |
|---|---|---|
| T-08 | 在每关目标动作前点击一个非法点。 | 主引擎 `boardMatrix`、`edges`、`turnCount`、`historyHashes`、当前玩家均不变；错误文本可读且可重试。 |
| T-09 | 点击一个规则合法但不是本关目标的点。 | 只在隔离副本中试算；教学主局面完全恢复；提示 `TUTORIAL_TARGET_MISMATCH`。 |
| T-10 | L3 点击空点和白方保护区点。 | 分别提示“必须落在敌线”和“起点保护区”；两次均不改局。 |
| T-11 | L3 成功切断。 | 反馈顺序能被视觉和读屏理解；清除数量由前后快照差异计算；减少动态效果仍完整。 |
| T-12 | L4 终局后点击棋盘或重复跳过。 | 返回/显示 `GAME_OVER`，不增加回合，不重播胜利动画；可重玩。 |

### 7.3 首次流程、移动端和无障碍

| ID | 操作 | 必须通过 |
|---|---|---|
| T-13 | 新访客进入并选择“第一次玩”。 | 不登录、不连接服务器即可创建 L1；首次说明、目标和主操作在首屏可见。 |
| T-14 | 完成四关后进入第一局。 | 显示真实规则版本和实际棋盘配置；不把教学 6 边长冒充普通模式默认配置；可返回/重玩。 |
| T-15 | 320 px 宽手机竖屏完成四关。 | 无横向滚动、目标点可触摸、主按钮不被遮挡、切断反馈可读。 |
| T-16 | 只使用键盘完成四关。 | 可聚焦目标动作/跳过/重玩/下一步；焦点可见；无键盘陷阱。 |
| T-17 | 开启屏幕阅读器。 | 能听到关卡目标、当前轮、成功和失败原因；非法动作不会静默。 |
| T-18 | 开启 `prefers-reduced-motion`。 | 不依赖动画完成理解；切断和结算仍有文本、状态和结果。 |
| T-19 | 在教学中切换 Guide/打开关闭阅读弹窗。 | 关闭后焦点回到原控件；教学状态不丢失；阅读内容不会宣称关卡已完成。 |
| T-20 | 让异步渲染/Worker 返回迟到结果（如后续接入）。 | 迟到结果不得覆盖更新后的教学局面；版本、关卡 ID 和 position revision 不匹配时丢弃。 |

## 8. v0.1 明确不承诺的内容

- 当前 Guide 的三个规则阅读版本不是交互教学；本规格不把它们写成已有 Tutorial。
- 当前 `GameController` 没有完整的本地非法原因映射；本规格中的细分原因和语义化反馈属于待实现。
- 当前 Canvas 没有可用的逐点键盘操作协议；仅有 `aria-label` 不算无障碍教学完成。
- 当前 Renderer 有合法落点标记、上一步环和提示点，但没有本规格的切断事件动画和断联差异说明。
- 当前普通对局的保存恢复、完整棋谱复盘和教学进度持久化不在本文件中承诺。
- 教学关卡只验证当前 Web `territory-v2` 规则；不能直接复用研究版、旧 Pygame 版或其他规则版本的 witness。
