# LIFELINE Lab 发布门槛与回归矩阵

制定日期：2026-09-21  
适用范围：LIFELINE Lab Web 产品、规则引擎、浏览器 AI、复盘/实验室展示和休闲联机。  
文档性质：发布门槛定义，不是当前版本通过证明。

## 0. 当前基线与判定语义

本次仅对仓库文档和测试脚本做了只读核对；没有启动服务器、没有运行下面的测试、没有运行长实验。因此本文不能把任何项目写成当前 `PASS`。

每个门只允许使用下列状态：

| 状态 | 含义 |
| --- | --- |
| `PASS-CURRENT` | 在目标提交、目标规则版本和声明环境上，本次有完整命令、退出码、日志/收据和哈希；人工项有记录。 |
| `PASS-HISTORICAL` | 旧提交、旧环境或历史报告曾通过；不能替代当前发布核验。 |
| `SMOKE-ONLY` / `PILOT-ONLY` | 采样、试运行或小规模探索；只能发现问题，不能证明正式门。 |
| `NOT-RUN` | 尚未执行，或只读检查未产生运行证据。 |
| `BLOCKED` | 命中阻断条件，或证据不足以作出正面判定。 |

发布结论必须由当前候选提交生成。历史研究中的 `formal_ready=true` 只说明对应研究任务的冻结身份、预算、重放和工件完整，不等于 Web 发布通过、用户体验通过或研究结论成立。

## 2. 规则版本、棋谱和跨实现边界

### 2.1 冻结契约

| 范围 | 当前约定 | 发布要求 |
| --- | --- | --- |
| Web 页面、新建房间 | 默认 `territory-v2` | 发布样例、golden state、回放和截图必须写明 `rulesVersion=territory-v2`。 |
| 裸 `new GameEngine()` | 默认 `territory-v1`，用于兼容旧调用/冻结样例 | 不得因页面升级静默改变 v1 语义；测试需显式构造 v1/v2。 |
| Python/Pygame | legacy v1 lineage | 不支持 v2；不得把“同一款游戏”写成逐状态一致。若要声称一致，须另有相同规则、输入和 golden-state 契约。 |
| `research/` | 各实验自己的冻结协议、源码/配置哈希和收据 | 研究结果不自动迁移到 Web；接入展品前须核对规则版本、棋盘、历史、动作语义和验证脚本。 |
| 棋谱 | 至少含 `schemaVersion`、`rulesVersion`、引擎构建标识、棋盘/玩家配置、合法行动序列和终局摘要 | 未知版本、版本不兼容、非法顺序、过大文件或哈希不符必须拒绝且不破坏当前对局。 |

### 2.2 可比字段

跨实现或回放一致性比较规则决定状态字段：棋盘节点、逻辑边、当前行动方、`historyHashes`/Superko 历史、连续跳过、认输集合、终局标志、离散 `area` 和赢家。缓存、`positionRevision`、Worker 时序等实现计数不要求相同。

只有在下列条件全部满足时，才允许写“跨实现一致”或“规则等价”：

1. 明确写出同一 `rulesVersion`、棋盘尺寸、玩家数、起始状态和动作编码；
2. 同一动作前缀在双方均合法，逐步比较上述规则决定字段；
3. 包含至少一个非首步密集局面、切断/断联、领土、Superko、跳过和认输分支；
4. 保存 golden-state、源码/配置哈希、命令、退出码和独立复核结果。

Superko 有真实的历史依赖；历史 pilot 中“影响罕见”不能改写为规则等价或可删除。研究 v1 witness 不得直接作为 Web v2 对局结论；若展示，标题、输入和结论必须显式标为研究版本/只读案例。

## 5. 人工测试最小脚本

每条人工用例记录：构建标识、规则版本、浏览器/设备、初始棋谱或动作前缀、预期、实际、录屏/截图路径、是否可重复。

1. **首局**：冷启动→完成四个教学场景→进入双人小盘→AI 先手/后手各一局→解释赢家和离散 `area`。
2. **规则**：在 6、9、15 和密集非首步局面执行扩张、攻击、断联清除、保护区、三点限制、Superko、跳过、认输；确认非法动作不改变状态。
3. **AI/提示**：AI 思考中取消、重开、换难度、落子后触发旧响应；确认旧 Worker 不得落子、不覆盖比分或回放。
4. **保存/复原**：每次确认后刷新；恢复后继续落子、跳过、认输；模拟存储失败并确认有可理解提示。
5. **复盘**：导出、导入、逐步前进/后退、终局；测试缺字段、未知版本、非法行动、过大文件；确认当前棋局不被破坏。
6. **联机**：注册/登录、房间、准备、动作同步、重复消息、乱序消息、刷新重连、重置、离房；确认本地 AI 首局不依赖联机。
7. **移动/可访问性**：真实手机竖屏窄宽度完成首局；触摸目标不重叠，按钮不溢出；键盘焦点、文本状态、非颜色提示和减少动态效果可用。
8. **发布/回滚**：干净环境加载发布包，确认版本/资源哈希/已知问题；按回滚目标恢复并再次打开核心闭环。

## 6. 性能、移动端与恢复门

### 6.1 性能

- 首次加载：声明设备、浏览器、网络和缓存状态；冷缓存至少 5 次，核心游戏可操作时间中位数 `≤3s`。
- 操作反馈：标准测试棋盘和密集局面，确认输入反馈 p95 `≤100ms`。若领土计算异步，必须显示 pending 状态且不得显示旧比分。
- AI：快速档多数落子 `≤2s`；较深档显示预算、可中止；记录每次实际用时和取消用时。发布前把“多数”的分母和样本数写入证据，不能用一次最快三秒内结果代替。
- 棋盘：至少覆盖 6、9、15；如果 15×15 达不到预算，必须显式标为高级、优化或缩小支持范围，禁止静默改变规则。
- Node benchmark 只产生描述性数据，不能单独满足上述目标；目标必须由声明设备上的真实浏览器测量支持。

### 6.2 移动端

- 发布前至少一台真实手机浏览器 `PASS-CURRENT`；桌面 Chrome/Edge 分别记录。
- 必查竖屏窄屏、触摸落点精度、预选/确认、滚动与缩放、AI 思考时操作禁用、错误提示、网络切换和恢复。
- Safari 未实测必须写 `NOT-COVERED`，不能使用 Chrome/Edge 结果推断 Safari 通过。

### 6.3 故障恢复

下列任一项在核心闭环中丢失棋局、错误改盘、显示旧结果或无明确恢复入口，直接阻断对应发布层级：

- AI/Hint/Territory Worker 超时、抛错、重复回调、取消后迟到回调；
- 刷新、重开、切换棋盘/规则后恢复到错误版本或错误历史；
- 损坏、未知版本、非法顺序、超大棋谱破坏当前棋局；
- 联机断网、重连、重复/乱序/错误归属消息导致重复动作或错误状态；
- 发布资源缺失、版本与资源哈希不匹配，或回滚后无法打开核心闭环。

长实验不属于本文件的发布前执行项；如未来启动，必须另按 `AGENTS.md` 的检查点、恢复、增量收据、重复 worker 防护、停止入口和独立监督要求执行。

## 7. 研究结果与产品文案边界

研究材料中的结果必须按原协议引用，并和产品状态分栏：

- `formal_ready=true`：仅表示对应冻结研究流水线的工件/任务门完成；不表示 Web 当前实现、模型质量、用户体验或论文接收。
- smoke/pilot/partial：只写“试运行/探索性/条件性证据”；不得写成当前发布通过或正式模型效果。
- Superko：历史结果可以说明历史依赖和条件性观察；不得写“规则等价”“可以删除 Superko”或“训练 agent 不受影响”。
- AI 文案：深度 2/3/4 是搜索配置；未经校准的估值不得显示为真实胜率；无充分搜索不得标“最佳/最优/致胜”。
- 研究对比：至少记录规则版本、棋盘尺寸、先后手、对手、模型/构建、预算、实际用时、样本数和是否为独立重复；重复确定轨迹不算独立重复。

## 9. 明确阻断条件

出现下列任一项，发布决策为 `HOLD` 或 `BLOCKED`，直到补证据、修复并重新运行受影响矩阵：

1. P0/P1 规则、比分、赢家、历史合法性、棋谱重放、迟到响应或恢复缺陷；
2. 当前候选只依赖旧提交、历史报告、旧截图、PID/旧日志、smoke/pilot 或部分完成收据；
3. 必需自动项未运行、非零退出、输出缺失、哈希不匹配，或无法证明测试针对目标提交；
4. 规则版本、棋盘尺寸、玩家数、起始状态或模型/构建未绑定，导致结果无法解释；
5. 将 Web v2、裸引擎 v1、Python legacy v1 或研究冻结协议混用而没有逐项边界；
6. 将 `formal_ready=true`、数值结果、benchmark、Worker shim 或 mock 网络测试升级为用户体验、跨实现一致、论文结论或正式发布通过；
7. 核心闭环在声明设备上无法完成，加载/操作/AI 目标未达标且没有明确降级或支持范围；
8. 移动端未测却宣称移动端通过，或未测 Safari 却宣称全浏览器通过；
9. 损坏输入、超时、断网、重连、回滚或资源缺失会静默丢失/篡改棋局；
10. 发布包缺版本、资源哈希、已知问题、回滚目标，或包含凭据、私钥、数据库、缓存、日志、检查点、原始轨迹等禁止产物；
11. 新增长实验没有检查点、可验证恢复、增量收据、重复 worker 防护、暂停/停止入口或独立监督；
12. 研究文案、AI 解释或发布页使用“最佳”“真实胜率”“规则等价”“已证明”“已接入模型”等超出证据边界的表述。

只有当目标层级的必需项全部为 `PASS-CURRENT`，可接受的限制均已在发布说明公开，且不存在未豁免阻断条件时，才能签署该层级发布。
