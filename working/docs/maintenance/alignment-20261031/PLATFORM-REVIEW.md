## 需要修复

1. **桌面离线时仍可能收集贡献对局。** `prepare-aligned-desktop-20261031.py:80–83` 只拦截 `flush()` 和用户 `toggle`。`TrainingContribution.js` 构造函数读取旧的 v3 同意，可能恢复 `enabled=true`；`OnlineApp.js:4736` 随后允许新局建立采集上下文，`:4933–4950` 终局调用 `enqueue` 并保存队列。贡献 UI 也可能显示开启，却无法切换。应以运行时能力限制采集及队列写入，保留原存储同意和待上传队列，并明确显示不可用；测试携带已有 opt-in 和待传队列的完整新局/终局。
2. **桌面隐藏联机入口不等于阻断后台重连。** 原宿主 `desktop/scripts/prepare-renderer-assets.mjs:36–46` 只给网络 Dock 和弹窗增加 `v-if`；桌面适配脚本没有给 51e `OnlineApp.js:6244–6306` 的重连/连接加能力检查。若存在已存房间且教程恢复路径到达 `:5596–5599`，仍调用 `attemptReconnect`；登录完成路径 `:6556–6558` 亦会调用。应在实际连接/重连边界阻断，覆盖旧会话、教程结束和离线启动的行为测试；保留存储，不应删除旧房间状态。
3. **补丁身份与文件集合未被验证。** 两个 prepare 脚本第 43–44 行只要传入任意存在的指南补丁文件，即接受任意 `different` 前端文件；第 54–57 行只记录补丁 hash，未应用补丁或证明它对应差异。`audit-platform-alignment.py:20–42` 只遍历 Git 参考树，未统计快照中的额外文件；后者仍被复制进候选。应从 51e 在隔离目录严格应用声明补丁，再比较完整路径集合及内容，包括新增、删除和未跟踪文件；之后分别记录输入、适配后和产物身份。Desktop 第 112 行末尾复验遗漏 `package.json`、lock 和三个复制的旧宿主模块，构建过程中变化不会触发输入漂移错误，应一并复验。

- **itch 开启贡献时投递目标不随配置变化。** `prepare-aligned-itch-20261031.py:72–78, 93–99` 接受并使用远程 WebSocket 配置、允许同时启用贡献，但 51e `TrainingContribution.js:183` 固定向相对路径 `/api/training/contributions` POST；在 itch iframe 下这是托管页的源，不是配置的服务地址。当前配置的网络和贡献均关闭，因此不影响本次默认离线候选。开启该组合前应明确拒绝或连接经校验的贡献 API，做实际目标验证。
