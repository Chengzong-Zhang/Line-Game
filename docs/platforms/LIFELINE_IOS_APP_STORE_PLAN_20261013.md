## 3. 第一阶段必须确认大陆发行路径

### 3.1 分清四件不同的事情

| 项目 | 作用 | 当前下一步 |
| --- | --- | --- |
| 软件著作权登记 | 整理和证明软件权属 | 复用已有三份草稿，确认办理进度与冻结版本，补齐事实字段、真实截图和代码材料 |
| 游戏出版审批／版号 | 大陆游戏发行的重要前提 | 寻找有对应资质的出版单位，确认申报类别与运营合作方式 |
| APP 备案 | 适用的 APP 互联网信息服务备案 | 由最终主体与接入服务商确认适用性和材料，不能直接拿网站备案代替 |
| Apple Developer Program | 苹果签名、测试分发及商店发布能力 | 确定上架主体与账号归属后办理；不能替代上述手续 |

苹果当前说明要求大陆区游戏提供批准编号及证明材料，包括 ISBN 核发文件／批复和营业执照等。该说明没有给本项目提供“免费或单机即可免版号”的依据。[Apple：中国大陆可用性要求](https://developer.apple.com/help/app-store-connect/reference/app-information/app-information/)

国家新闻出版署的国产网络游戏审批指南列明出版单位资质、运营机构条件及权属材料。个人作为著作权人与承担出版／运营职能是不同角色；软著是权属材料的一种，不能据此直接取得游戏发行资格。先由具资质出版单位确认本项目的申报路径。[国家新闻出版署办事指南](https://www.nppa.gov.cn/bsfw/xksx/cbfxl/wlcbfwspsx/202210/t20221013_600725.html)

对于在境内提供互联网信息服务的 APP，应按适用规则办理 APP 备案；已有网站备案可减少部分重复资料，但仍有 APP 信息需补充。纯离线首版具体如何适用，应在发行方案中明确。[工信部 APP 备案通知](https://www.miit.gov.cn/jgsj/xgj/wjfb/art/2023/art_dd783a581c9644a4aee10afa582811db.html)

### 3.2 出版／发行合作的执行清单

1. 整理一份介绍包：游戏玩法、现有网页演示、目标平台、首版功能、是否联网／收费、内容与素材来源、拟用中文名称。
2. 在支付软著登记服务费用前，核查“生命线 / LIFELINE”的命名、同名与品牌风险，协调软件全称、简称、出版申报名及商店名。不能承诺某名称一定可用。
3. 用户或获明确授权的负责人向 2–3 家有相关经验的出版／发行单位咨询，取得书面范围与报价；本计划不代表已经联系这些单位。
4. 明确出版单位、运营单位、苹果上架账号持有人；确认是否需要实名与防沉迷、采用哪类申报材料、APP 备案与相关经营资质由谁承担。
5. 合作文件明确知识产权归属、授权范围、收费／分成、维护责任、账号及 Bundle ID 控制权、用户数据责任和终止合作后的处理。
6. 获得可执行路径后冻结首版内容；后续重大玩法、联网及收费变更先核对是否影响已申报范围。

建议优先评估“保留你的游戏知识产权，由合适的出版与运营合作方承担相应职能”。是否自行设立公司应根据实际合作条件决定，不作为先做技术样机的必需动作。

**通过条件 G0：** 有具体负责人、适用申报路径、主体安排、材料清单、预算与下一步。咨询完成不代表获批。若尚无可行合作路径，可以继续有界技术验证与软著材料准备，但公开大陆上架日期保持未确定。

## 5. 技术选择与改造点

### 5.1 推荐架构

```text
iPhone / iPad 应用
  ├─ Capacitor / WKWebView：运行随包安装的游戏资源
  │   ├─ Vue 界面、Canvas 棋盘、教学、复盘
  │   ├─ GameEngine：territory-v2 规则与计分
  │   └─ Workers：AI、提示、领土计算
  └─ 平台适配层
      ├─ 对局存档、设置与版本迁移
      ├─ 文件导入导出、系统分享、触感反馈
      └─ 前后台切换与恢复

后续联网版：显式配置 HTTPS / WSS → 既有 Python 服务
```

Capacitor 官方提供 JavaScript 与 iOS 原生能力桥接，使用 WKWebView。当前 v8 文档列出 iOS 15+ 和 Xcode 26+；实际最低系统以选定插件、用户设备和完整测试矩阵确定。[Capacitor iOS 文档](https://capacitorjs.com/docs/ios)

| 路线 | 判断 |
| --- | --- |
| Capacitor + 复用 Web 核心 | 首选；保留规则、AI 与回放的一套主实现，新增平台层 |
| SwiftUI / SpriteKit 全面重写 | 适合以后有明确原生瓶颈时局部采用；首版会引入重复实现与规则回归成本 |
| Unity / Flutter / React Native 重写 | 当前收益不足以支撑整体迁移；与现有成熟模块的复用关系较弱 |
| 直接加载线上网页的容器 | 离线与版本稳定性差，不作为生产方案 |
| PWA | 可作为开发中的体验渠道；不能计作 App Store 目标完成 |

苹果 4.2 关注完整应用体验。原创游戏、离线内容、可靠恢复和系统文件操作能支撑产品价值，但采用某个框架或添加几个原生按钮都不保证审核通过。核心代码随应用版本提交，首版不设计绕过审核的远程功能更新。[App Review Guidelines：4.2、2.5.2](https://developer.apple.com/app-store/review/guidelines/)

### 5.2 根据当前源码必须处理的事项

| 改造项 | 当前事实 | 实施要求 |
| --- | --- | --- |
| 离线启动 | `main.js` 从 CDN 加载 Vue，`index.html` 从 CDN 加载 MathJax | 固定依赖版本与许可；游戏、教学、字体、图片等必需资源随包安装；纯离线冷启动通过 |
| 可重复构建 | 当前以浏览器 ES modules 和 URL 缓存版本组织资源 | 新增包管理与锁文件、构建白名单；验证 Worker 和静态资产路径；不从整个仓库直接复制入包 |
| 运行环境配置 | WebSocket 依赖网页 `location`；贡献上传使用相对 `/api/` | 抽出平台配置；离线版不初始化这些服务；联网版显式设置 HTTPS/WSS、CORS 和鉴权 |
| 持久化 | `LocalGameSession.js` 使用同步 `localStorage` | 设置用 Preferences；棋谱用应用目录文件等持久化；引入异步存储接口、完整性校验和上一份有效备份 |
| 前后台与进程回收 | Web 保存不等于 iOS 生命周期保障 | 每次确认行动后持久保存；后台取消搜索；恢复时检查对局标识和 revision，拒绝旧 Worker 结果 |
| 文件操作 | 网页下载／文件选择不能直接视为原生完成 | 接入系统分享和文件选取，验收 iPad 分享弹窗、取消和异常路径 |
| 精确触摸 | Canvas 已有响应式实现 | 点位命中随实际尺寸校准；15 边长提供放大或预览确认；按钮目标至少 44 pt；手势不误触落子 |
| 研究模型完整性 | ResearchAI 强制 SHA-256；ModelFreeAI 在缺少 `crypto.subtle` 时目前返回空哈希 | 在 WKWebView 验证二进制 fetch 与哈希能力；应用发布策略要求无法校验时明确失败／降级，不默默略过校验 |
| 训练数据贡献 | `TrainingContribution.js` 初始 `enabled = true`，恢复已有选择 | 离线首版不创建上传实例；后续应用版必须独立征得选择，不能把网页默认状态直接迁移成同意 |

Preferences 适合轻量设置，不作为大量棋谱数据库。Capacitor 官方提示移动系统可能清理 Web `localStorage`，并说明相关插件需要隐私清单声明。[Preferences 文档](https://capacitorjs.com/docs/apis/preferences)

建议新增独立的 `mobile/` 构建与平台目录；Web 核心继续共享。拆出 `PlatformServices`、`SaveRepository`、`ShareService` 等最小边界即可，不先做整个 `OnlineApp.js` 的大重写。正式目录和依赖版本在技术验证后冻结。

### 5.3 规则、AI 与存档契约

- 复用 Web `territory-v2` 为产品规则真源，保留裸引擎 v1 兼容语义；不要切换到 Python 引擎来“顺便原生化”。
- 恢复必须带规则版本、设置、行动序列和玩家配置；由完整重放恢复 Superko 历史。只保存棋盘图片或占用数组不足以恢复合法性。
- Worker 结果继续验证请求、对局／引擎身份、revision、规则版本及行动方；切后台、重开、复盘和返回后都不能落入旧结果。
- 以既有 AI 档位为测试起点。若为手机新增时间预算或减小搜索规模，应明确记作新产品档位及质量取舍，不宣称“同棋力纯提速”。
- 研究模型作为可选内容保留来源与兼容性标记，不因导出或浏览器测试通过就称为最强模型。当前报告仍记录 Python/Web 两处终局计分差异；该问题限制跨实现与棋力声明，不要求为复用同一 Web 引擎的首版重做全部研究实验。
- Safari 网页数据与独立应用数据不自动共享。提供网页导出棋谱→应用“文件”导入的迁移路径；应用升级测试和卸载后重新安装是两种不同情况。

## 6. 没有 Mac 的推进方式

| 工作 | Windows 可推进 | 需要苹果环境／用户操作 |
| --- | --- | --- |
| 梳理源码、离线资源、规则和回放回归 | 是 | 真机结论仍需后补 |
| 平台接口、构建配置、素材、隐私资料草案 | 大部分可以 | 原生插件实际效果需验证 |
| iOS 编译、签名、安装、Xcode 诊断 | 不能只依靠当前 Windows 完成 | 可用 Mac 或合适的 macOS 构建服务 |
| 真机交互与生命周期验收 | 不能由桌面模拟替代 | 使用已有 iPhone 和 iPad；本地可连接 Mac 更便利 |
| 苹果身份验证、付费与法律协议 | 准备材料 | 账号持有人完成身份及协议动作 |

优先顺序：**借用可运行当前 Xcode 的 Mac → 短期租用合适的 Mac → 有持续维护需求后再考虑购买**。云 Mac 可用于构建，但不能默认它能直接连接你手上的设备完成现场调试；TestFlight 分发、崩溃反馈与本地连接各自解决的问题不同。[Capacitor 环境要求](https://capacitorjs.com/docs/getting-started/environment-setup)

Apple Developer Program 当前公布年费为 99 美元，按地区以当地币种收费；个人账号会显示个人法定姓名，组织账号需满足主体验证条件。先与发行安排确定持有人，避免过早建错归属。使用 Xcode 在自己设备做有限测试可以不先购买会员；TestFlight／商店分发另需相应会员能力。[Apple 会员与注册说明](https://developer.apple.com/help/account/membership/program-enrollment/)

截至本次查询，苹果自 2026-04-28 起要求上传 App Store Connect 的构建使用 Xcode 26+ 和对应 iOS / iPadOS 26 SDK。**构建 SDK 要求不等于最低运行系统必须为 26**；提审前再次核对要求。[Apple SDK 要求](https://developer.apple.com/news/upcoming-requirements/?id=04282026a)

## 7. 分阶段执行、交付与通过条件

以下是熟悉现有项目的开发者持续投入、有可用 Mac 和真机配合时的工程估算。软件工作可以与发行资料准备并行；审批、合作谈判、账号验证和设备等待另计。

| 阶段 | 预计投入 | 工作与交付 | 通过条件 |
| --- | --- | --- | --- |
| G0 发行可行性 | 首轮 3–7 工作日，后续持续 | 主体／合作路径、既有软著材料核对、名称、预算、适用要求 | 能说明由谁以什么路径推进；不是要求此时拿到版号 |
| M0 基线与支持范围 | 1–2 工作日 | 冻结 Web 源码和资产清单；登记 iPhone/iPad；形成首版功能表 | 基线可复现，现有工作保留，设备／系统／功能范围明确 |
| M1 真机技术验证 | 3–5 工作日 | 最小 iOS 样机：启动、落子、一个 AI Worker、保存恢复、文件样例 | iPhone 和 iPad 实际 WKWebView 可用；5/9/15 尺寸暴露性能与输入问题 |
| M2 离线与构建 | 4–6 工作日 | 本地资源、锁文件、构建、运行开关；教学→对局→终局→复盘闭环 | 全新安装后断网可完成首局；没有依赖 CDN 的隐性阻断 |
| M3 原生体验与稳定性 | 6–9 工作日 | 存档、生命周期、系统分享、设备布局、AI 档位与失败恢复 | 真机恢复与关键交互通过，无丢局或迟到落子 |
| M4 测试与发布准备 | 5–8 工作日 | TestFlight 候选、8–12 人目标试用、缺陷修复、隐私与商店资料 | 阻断项关闭，测试构建和拟提审构建身份可对应 |
| M5 提审与大陆上线 | 准备约 2–4 工作日，审核时间另计 | 资质、备案适用材料、商店元数据、审核说明、版本、发布操作 | 苹果批准且大陆区域实际可下载；安装后核心路径复验 |

工程按 **约 5–8 周达到提审准备** 规划，正式启动后依据 M1 测量重新估算。若必须将联网／实名接入纳入首版，或 WKWebView 性能无法达到核心体验，应另行调整范围和工期。

大陆发行时间不能用工程工期代替。出版审批指南列出受理后的许可期限，但前期合作、材料整理、受理、补正等不能据此压缩成固定上线承诺；当前无版号、无合作方的状态下，应按可能跨数月的外部依赖管理。[审批流程与期限](https://www.nppa.gov.cn/bsfw/xksx/cbfxl/wlcbfwspsx/202210/t20221013_600725.html)

M1 的退出决策：资源路径或桥接问题优先局部修复；AI 慢则测量后选择适合手机的公开档位；只有证据表明核心体验无法实现时，才重新评估局部原生实现。不要在未做真机样机前启动全量重写。

## 8. 真机验收与证据要求

下表均为**计划目标，状态 NOT-RUN**。没有真实 iOS 构建与测试记录时不得标记通过。

| 项目 | 预设验收方式 |
| --- | --- |
| 离线完整性 | 新安装、首次启动前断网；教学、人机、终局、复盘、规则和存档完整可用 |
| 规则一致 | 固定动作与局面比较网页/iOS 的节点、逻辑边、历史合法性、比分、跳过、认输和赢家 |
| AI 与 Worker | 在两台设备完成先后手对局；重开／退出／切后台时取消，不接受过期结果；覆盖 Worker 失败 |
| 生命周期 | 每台设备至少 20 次有记录的中断／恢复，覆盖落子后、AI 思考中、复盘、锁屏、系统终止后重启 |
| 文件及升级 | 导出→关闭→导入→重放一致；损坏／未知版本／超大文件不破坏原局；升级候选保留旧存档 |
| 手机与平板操作 | 所有公开尺寸可选点；5/9/15 重点测试密集局面；iPad 旋转、窗口调整及分享弹窗正常 |
| 初始性能目标 | 较慢的测试设备上，至少 5 次离线冷启动，中位数不超过 3 秒；输入可见反馈 p95 不超过 100 ms |
| AI 性能目标 | 固定局面集记录完整分布，快速档目标 p95 不超过 2 秒；更慢档可取消且显示状态；超标须调整公开范围或明确取舍 |
| 持续使用 | 两台设备各至少一段 30 分钟实际使用，记录发热、内存、崩溃与响应；不能由一次启动推断长期稳定 |
| 新人试用 | 目标 8–12 人，至少 80% 无口头帮助完成教学和开始对局；保留实际人数和任务结果 |
| 发布阻断 | 无导致崩溃、丢局、错判胜负、隐私选择失效或无法完成首局的未修复问题 |

阈值是工程目标，不是已经测得的数据。M0 固定设备、局面集、测量方式和分母；若修改阈值或功能范围，应记录原因，不能测后改数字以制造通过。

复用现有验证入口：规则 `verify-territory-v2.mjs`；AI `verify-ai-control-flow.mjs` / `verify-local-ai-session.mjs` / `verify-hint-worker.mjs`；存档 `verify-local-game-session.mjs`；棋谱 `verify-replay-codec.mjs`；教学 `verify-tutorial.mjs` / `verify-tutorial-session.mjs`；输入 `verify-board-input.mjs`。保留研究模型、联网、训练贡献时分别加入对应回归。每次只运行与改动有关的测试，再补真实设备验证。

每份应用验收记录包含：源码快照与哈希、规则／存档版本、应用 build number、签名构建身份、设备／系统、命令／操作步骤、结果和已知问题。历史网页 PASS 只能标为历史依据。

## 9. 隐私、商店材料与上线运维

首版隐私策略建议：核心游戏无需网络采集；训练贡献不启用；不加入广告、跟踪或第三方统计 SDK。若发行要求需要实名，按最终服务真实数据流重新编制隐私说明。数据收集标签、隐私政策及隐私清单分别核对，不能因为自称“匿名”就填写“未收集数据”。[Apple 隐私资料](https://developer.apple.com/help/app-store-connect/manage-app-information/manage-app-privacy/)

后续保留注册功能时，应具备应用内账号删除与相关数据处理路径；不能只给退出登录。当前源码检索未找到明确的账号删除入口，应在联网版本中专门核实和实现。[Apple 账号删除要求](https://developer.apple.com/help/app-review/guideline-reference/5-1-1-account-deletion)

商店提审包应包含：

- 应用图标与启动外观；真实 iPhone / iPad 截图；准确的中英文描述、关键词和版本说明。
- 正式名称、Bundle ID、版本号、年龄分级问卷、支持地址与公开可访问的隐私政策；分级以实际问卷为准。
- 字体、音效、图片、第三方库和模型来源的权利／许可清单；现有网站可访问不等于其中所有内容都可随应用分发。
- 游戏批准材料、匹配的主体与授权文件、适用的 APP 备案材料；这些信息必须与提审产品一致。
- 若有登录，提供有效审核账号和可用服务；离线版本给出教学、对局、恢复、复盘的明确审核步骤。
- 原生插件使用的隐私清单及 Required Reason API 说明；加密／出口合规问卷按实际技术填写。

TestFlight 是测试分发渠道，外部测试涉及 Beta App Review；它不是大陆商店正式发行资格，也不是永久替代商店的分发方式。[Apple TestFlight 指南](https://developer.apple.com/tutorials/develop-in-swift/test-your-beta-app)

发布安排：首发使用手动发布；获准后核实中国大陆 storefront 可见性、下载与安装，记录用户真实设备的最终验证。后续版本可评估分阶段发布。应用更新与网页原子切换不同：用户已经安装的版本不能瞬间降回旧包，故障应通过停止后续分发、兼容服务与修复版本处理。

上线后前两周重点处理崩溃、恢复失败、评价中重复问题和客服反馈；之后再决定联网版与模型扩充。反馈与数据采集按已声明的隐私方案运行。

## 11. 立即可执行的首周清单

1. 记录 iPhone / iPad 机型和系统，找到可借用／短租且支持当前 Xcode 的 Mac。
2. 读取已有三份软著草稿，确认是否已实名认证／提交，固定本次申报名称、权利人和冻结版本；在保留原稿的前提下补齐源码、说明、截图与素材许可。
3. 确认出版／发行咨询对象和书面问题，取得适用路径；有明确授权后再联系外部机构。
4. 从发布清单恢复可复现的 Web 基线，保留当前所有修改；实现时使用独立且合适的 `codex/` 工作分支／工作区。
5. 在 Windows 完成资源依赖清单，在 Mac 上安装最小 iOS 样机；真机验证 Worker、密集棋盘、存档和断网启动。
6. 根据 G0 与 M1 结果冻结 1.0 范围、预算、上架主体及正式排期，再办理对应会员和后续开发。
