# 三人 AI v2 后训练

v2 从 v1 的 16 维线性策略权重开始，以新生成的三人对局微调权重。
v1 模型、特征代码、规则引擎和原训练证据保持原样。v2 的模型文件、协议、
训练目录和验证结果独立保存；是否作为网页默认模型，由独立最终对局评估决定。

## 本次结果（2026-10-21）

**后训练和微调已完成，训练与最终评估的独立复核均通过，但 v2 未达到晋级门槛，
本地网页继续默认使用 v1。** v2 作为未晋级候选保存，可由模型加载器明确指定，
不会自动替换正常对局中的 AI。本轮没有服务器部署或小程序同步。

- 从 v1 初始化，完成 900 轮 Adam；新增 1,324 个训练局面、446 个验证局面。
  共生成 72 条轨迹，其中 54 条真实终局、18 条截断；截断轨迹仅用于模仿训练。
- 验证交叉熵从 1.598751 降至 1.524806。171 局开发对战全部终局，
  按预先确定的规则选出第 900 轮候选；这些结果不代表独立棋力提升。
- 独立最终评估完成 126 局，无截断，覆盖尺寸 5 / 7 / 9、三个先手和
  单 AI / 双 AI 阵容。独立复核重放 4,973 个动作并核对 4,595 次策略决定。
- 相对 v1 的平均共享胜分差为 **−3.24 个百分点**，18 个随机前缀簇的
  95% bootstrap 区间为 **[−8.56, +2.31] 个百分点**。
  区间跨越 0，未证明棋力提高，也不能据此声称已证明显著更弱。

## 固定训练方法

- 规则真源：Web `GameEngine.js` 的 `territory-v2`，保留 Superko、
  实际行动方、自动跳过、终局与真实离散 `area` 计分。
- 教师：三步 MaxN。每个分支返回三名玩家的完整收益向量，
  每层按引擎实际 `currentPlayer` 最大化该玩家自己的分量。
  正常轮转下三步覆盖三人各一次行动；自动跳过时不假定固定轮转。
- 根节点的每个合法动作都得到训练目标。后续两层只展开启发式排序前四个动作，
  因而这是有界搜索教师，不是完整树最优解。
- 非终局叶子使用节点、连线和可达空间的启发式优势。终局叶子使用真实
  `area` 得到的领先者及平分胜分，不能用启发式估计替代终局输赢。
- 训练尺寸 5、7、9，起始座位 BLACK、WHITE、PURPLE。
  每个尺寸与座位组合含六个训练轨迹、两个验证轨迹，共 54 / 18 个轨迹。
  两组使用不同完整轨迹和不同种子，不把同一对局的各步拆入两组。
- 每个轨迹最多 48 步；未终局的轨迹标为截断，仅作为局面模仿数据，
  不计作对局胜负结果。
- 采样行为混合 v1 策略、三步教师与随机合法动作，概率分别为 0.45、0.35、0.20。
  训练目标是教师对全部合法根动作的 softmax，温度 30。
- 全批量 Adam 运行 900 轮，学习率 0.03；对 v1 父权重有系数 0.0005 的 L2 约束。
  这是 weights-only warm start：继承策略权重，重新初始化优化器及随机数据生成状态。

固定候选检查点为第 200、500、900 轮。候选在独立开发前缀上与 v1 对战：
三个尺寸、三个起始座位、一个开发前缀，分别覆盖一个 AI 的三个座位和
两个 AI 的三种组合。九个全 v1 基线被三个候选共同复用，总共 171 个真实终局。
先按相同前缀/座位下的平均胜分增量选择，验证交叉熵与较早轮数依次用于打破平局。
开发对局一旦超出 360 步上限，流程停止，不用截断局面的估值代替胜负。

开发选择完成后只输出一个冻结候选。独立最终评估的种子和结果不进入训练、
检查点选择或调参。开发胜分、验证交叉熵、最终对局表现和本地网页验证是不同证据。

## 模型契约

模型沿用 `lifeline-three-player-policy` schema version 1：

```json
{
  "id": "three-player-policy-v2",
  "rules_version": "territory-v2",
  "temperature": 1,
  "lineage": {
    "type": "weights-only-warm-start",
    "parent_id": "three-player-policy-v1",
    "parent_sha256": "..."
  }
}
```

`features` 严格保持 v1 的 16 维顺序，`weights` 为 16 个有限数。
`training.two_player_samples` 和 `training.three_player_samples` 是父模型的来源数量，
新增训练数量分别记入 `posttraining_samples` 与 `validation_samples`。
源码、配置、父模型、选定轮数和开发汇总均写入模型来源信息。
输出模型一经冻结只按字节复制，不因最终评估结果修改其元数据。

支持推理的尺寸仍为 5–15；10–15 没有参加这次训练，不能声称已验证这些尺寸上的
棋力提升。实际页面使用独立加载器校验版本、来源与模型 SHA-256。

## 本地运行与恢复

固定协议：`web/tools/configs/three-player-policy-v2.json`。
本次运行目录：`local_artifacts/three-player-ai-posttrain-v2-20261021`。
该目录中的 `job.json` 绑定七个输入源/模型文件，监督器另绑定自身源码。

```powershell
node 'web/tools/supervise-three-player-job.mjs' --job 'C:\coding\py\line game\local_artifacts\three-player-ai-posttrain-v2-20261021\job.json'
```

独立监督由调用方以隐藏后台进程启动；单 worker 预算 600 秒、
监督硬超时 660 秒、整个任务墙钟预算 1800 秒，最多三次异常恢复。
worker 本身不负责启动后台监督者。

在运行目录创建 `PAUSE` 或 `STOP` 文件会保留当前进度并退出。
恢复前须按用户意图移除对应哨兵，再以相同 job 调用监督器的 `--resume`。
不删除检查点、完成的轨迹或旧证据来强行恢复。

每个生成/开发动作提交后保存完整动作前缀与 RNG 状态；
每轮优化保存权重、Adam 一阶/二阶矩和轮数。完整训练轨迹另存为带完整性校验的
独立单元，已完成的单元不再生成。开发终局保存种子、阵容、候选轮数、步数与真实分数；
可用冻结候选和确定性策略重建整局复核。

检查点与进度均先写临时文件再替换；Windows 短暂文件占用使用有界重试。
中断遗留的临时写入会隔离保留。OS 独占租约防止同目录出现重复 worker，
进程结束时自动释放。源码、配置、父模型或检查点损坏会终止恢复。
退出码：0 完成；75 暂停/停止/预算让出，需读取状态区分；
78 不可重试的证据/配置错误；1 为可由监督器有限重试的异常。
